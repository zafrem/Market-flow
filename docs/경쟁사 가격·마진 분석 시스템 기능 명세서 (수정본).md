# 경쟁사 가격·마진 분석 시스템 기능 명세서 (수정본)

Nov 12, 2026 · @Mark

## 1. 개요

원안의 4개 모듈 구조는 유지하고, 우선순위(P0\~P2)·수용 기준·비기능 요건을 추가했으며 매칭·시점 재현·마진 시뮬레이션의 정의를 구체화했다. 문서 안의 수치 기준은 모두 제안값이며 착수 전 확정이 필요하다.

| 영역 | 원안 | 수정본 |
| --- | --- | --- |
| 범위 | 전 기능 동시 나열 | P0(MVP)·P1·P2 단계와 단계별 진입 조건 |
| SKU 매칭 | 자동 매칭 엔진 한 줄 | 매칭 등급, 신뢰도 점수, 검수 큐, 정확도 목표 |
| 시점 재현 | event\_timestamp 기준 적재 | 발생 시점과 적재 시점을 함께 관리(이중 시점) |
| 가격 비교 | 경쟁사 할인가 | 쿠폰·배송비·증정을 반영한 실구매가 |
| 마진 시뮬레이션 | 마진율 변화와 BEP 수량 | 계산식 명시, 판매량 반응 시나리오 추가 |
| 수집 주기 | 실시간 | 등급별 주기와 SLA로 대체 |
| 운영 | 알림 발송 | 임계값·중복 제거, 가격 변경 승인 흐름 |
| 비기능 | 없음 | 권한·감사 로그, 비식별화, 데이터 품질 모니터링 |

## 2. 범위와 단계

P0는 카테고리 1개에서 상위 SKU 100\~200개를 수동 매칭해 가격/마진 비교 시트와 역마진 경고만 제공한다. 매칭 품질과 마진 계산이 검증된 뒤에만 다음 단계로 넘어간다.

| 단계 | 포함 기능 | 진입 조건(제안값) |
| --- | --- | --- |
| P0 (MVP) | ERP·자사몰 DB 연동, 타깃 SKU 가격 크롤러, 수동 SKU 매칭, 단가 환산, 순마진율 계산, 최저가 매칭 시뮬레이터(고정 수량), 마진 방어선 체크, 가격/마진 비교 시트, 권한·감사 로그 | 크롤링 법무 검토 완료, ERP 원가 항목 정의 확정 |
| P1 | 자동 매칭 + 검수 큐, 검색 로그·프로모션 원장 연동, 배치 백필, 시점 재현, 카테고리 분류기, 동의어 사전, 키워드 연산, 검색-판매 간극 진단, 알림, 프로모션 캘린더, 가격 변경 승인 흐름 | P0 마진율이 재무 수치와 ±0.5%p 이내로 일치, 크롤링 수집 성공률 95% 이상 2주 유지 |
| P2 | 전단지 파서, 메인 배너·기획전 수집, 신규 상품 감지, 할인 기간 이상 감지, 판매량 반응 시나리오 | 자동 매칭 정밀도 95% 이상, 백필 데이터 12개월 이상 확보 |

각 기능의 상세 요건과 수용 기준은 모듈별 절에 있다.

## 3. 전제와 용어

"실시간"이라는 표현은 쓰지 않고 수집 주기와 데이터 기준 시각으로 표기한다. 규모(SKU 수, 경쟁사 수)는 미확정이며 9절에서 확정한다.

| 용어 | 정의 |
| --- | --- |
| 실구매가 | 표시가 − 즉시할인 − 공개 쿠폰 + 배송비. 증정 행사는 단가로 환산(1+1은 개당 50%). 카드·멤버십 전용가는 별도 컬럼으로 병기 |
| 표준 단가 | 실구매가를 100g당, 100ml당 또는 개당으로 환산한 값 |
| 순마진율 | (판매가 − 매입원가 − 물류비 − 플랫폼 수수료 − 폐기 비용) ÷ 판매가 |
| 발생 시점 | 값이 실제로 유효했던 시각(가격 적용일, 행사 기간) |
| 적재 시점 | 시스템이 그 값을 알게 된 시각. 소급 수정 추적에 사용 |
| 매칭 등급 | 동일(같은 상품), 유사(브랜드·규격만 다름), 대체(용도가 같은 다른 상품) |
| 데이터 기준 시각 | 화면에 표시된 값이 마지막으로 수집·갱신된 시각. 모든 가격·마진 수치 옆에 표시 |

수집 주기(제안값)는 다음과 같다.

| 대상 | 주기 |
| --- | --- |
| 핵심 타깃 SKU의 경쟁사 가격 | 1시간 |
| 그 외 매칭 SKU의 경쟁사 가격 | 1일 1회 |
| ERP 원가·재고 | ERP 배치 주기를 따름(확인 필요) |
| 자사몰 판매·주문, 검색 로그 | 1일 1회 |

## 4. 모듈 1: 데이터 수집 및 연동

모든 적재 데이터는 발생 시점과 적재 시점을 함께 가지며, 수집 실패는 조용히 넘어가지 않고 품질 지표로 드러나야 한다.

| 기능 | 단계 | 요건 | 수용 기준 |
| --- | --- | --- | --- |
| 멀티 소스 커넥터 | P0: ERP·자사몰 DB / P1: 검색 로그·프로모션 원장·파일 | 소스별 개별 파이프라인과 스케줄. 읽기 전용 계정 사용. 실패 시 재시도 후 알림 | 파이프라인별 마지막 성공 시각과 적재 건수가 관리 화면에 표시됨. 원천 대비 건수 차이 0.1% 이내 |
| 통합 스키마 매퍼 | P0 | SKU·매장·카테고리 코드를 표준 키로 매핑. 매핑 규칙은 버전 관리. P0는 설정 파일, UI는 P1 | 매핑되지 않은 코드가 목록으로 조회됨. 미매핑 행은 집계에서 제외되고 건수가 표시됨 |
| 배치 백필 업로더 | P1 | 과거 검색·판매·할인 이력 일괄 업로드. 업로드 전 스키마·기간·중복 검증. 같은 파일 재업로드 시 중복 적재 없음 | 검증 실패 행이 사유와 함께 내려받기됨. 재업로드 후 건수 불변 |
| 시점 스냅샷 재현 | P1 | 임의 과거 날짜의 원가·판매가·행사 상태 복원. "당시 알던 값"과 "현재 알고 있는 값" 중 선택 가능 | 검증용 과거 날짜 10개에서 ERP 마감 수치와 일치. 원가 소급 수정 후에도 수정 전 스냅샷 조회 가능 |
| 경쟁사 가격 크롤러 | P0: 타깃 SKU 가격 / P2: 메인 배너·기획전 | 표시가, 할인, 공개 쿠폰, 배송비, 품절 여부 수집. 요청 간격 제한, robots.txt 준수. 페이지 구조 변경 감지 | 주기 내 수집 성공률 95% 이상. 실패·구조 변경 시 1시간 내 알림. 표본 50건 수기 대조 시 가격 일치율 99% 이상 |
| 경쟁사 전단지 파서 | P2 | 이미지·PDF에서 상품명, 행사가, 기간, 증정 조건 추출. 필드별 신뢰도 제공. 검수 화면에서 원본과 나란히 확인·수정 | 검수 전 행사가 필드 정확도 95% 이상. 검수 완료 전 데이터는 분석에 반영되지 않음 |

## 5. 모듈 2: 데이터 정규화 및 매칭

마진 계산과 알림에는 사람이 확정한 "동일" 등급 매칭만 사용한다. 자동 매칭은 후보를 제안할 뿐이며 확정은 검수를 거친다.

| 기능 | 단계 | 요건 | 수용 기준 |
| --- | --- | --- | --- |
| 수동 SKU 매칭 | P0 | 자사 SKU와 경쟁사 상품 URL을 1:N으로 등록. 매칭 등급(동일·유사·대체)과 등록자·일시 기록 | 매칭 등록·수정·해제 이력이 조회됨. 경쟁사 상품이 단종·URL 변경되면 재확인 대상으로 표시됨 |
| 단가 환산 | P0 | 중량·용량·입수를 파싱해 표준 단가 산출. 신선식품은 등급·원산지·부위를 속성으로 보관하고, 속성이 다르면 "동일" 등급 불가 | 단위 파싱 실패 상품이 목록으로 조회됨. 표본 100건 수기 대조 시 환산 오류 1% 이하 |
| 자동 매칭 엔진 + 검수 큐 | P1 | 후보마다 신뢰도 점수 산출. 임계값 이상도 검수자가 승인해야 확정. 검수 결과는 평가 데이터로 축적 | 검수 표본 기준 정밀도 95% 이상, 재현율 80% 이상. 월 1회 표본 재평가 |
| 카테고리 자동 분류기 | P1 | 검색어·자사 상품·경쟁사 상품을 사내 표준 카테고리로 태깅. 신뢰도 낮은 건은 미분류로 분리 | 최하위 카테고리 기준 정확도 90% 이상. 수동 정정 가능 |
| 유사어·동의어 사전 | P1 | 브랜드명·줄임말·오타를 표준 키워드로 묶음. 변경 이력 관리 | 사전 변경이 다음 배치부터 집계에 반영됨. 변경 전후 영향 키워드 수가 표시됨 |

## 6. 모듈 3: 분석 및 시뮬레이션 엔진

모든 계산은 아래 식을 따르며, 비교 기준은 경쟁사 표시가가 아니라 실구매가의 표준 단가다.

```latex
\text{순마진율} = \frac{P - C_{\text{매입}} - C_{\text{물류}} - C_{\text{수수료}} - C_{\text{폐기}}}{P}
```

```latex
Q_{\text{BEP}} = Q_{\text{현재}} \times \frac{P_{\text{현재}} - C}{P_{\text{인하}} - C}
```

P는 판매가, C는 단위당 총비용, Q는 기간 판매량이다. 두 번째 식은 가격 인하 후 현재와 같은 총이익을 내는 데 필요한 판매량이며, 인하가가 총비용 이하면 "달성 불가"로 표시한다. 수수료가 판매가 비례이면 인하가 기준으로 다시 계산한다.

### 가격 및 마진

| 기능 | 단계 | 요건 | 수용 기준 |
| --- | --- | --- | --- |
| 순마진율 계산기 | P0 | ERP 원가 항목과 현재 판매가로 SKU별 산출. 폐기 비용은 카테고리 평균 폐기율 배분(SKU별 데이터가 있으면 우선). 원가 기준 시각 표시 | 재무 마감 수치와 ±0.5%p 이내. 원가 항목이 빠진 SKU는 계산하지 않고 사유 표시 |
| 최저가 매칭 시뮬레이터 | P0 | 경쟁사 실구매가에 맞출 때의 예상 순마진율과 BEP 판매량 산출. "동일" 등급 매칭만 대상 | 위 식과 수기 계산 결과 일치. 품절인 경쟁사 가격은 비교에서 제외 |
| 판매량 반응 시나리오 | P2 | 과거 행사 데이터로 추정한 탄력성으로 인하 후 예상 판매량과 총이익을 비관·기준·낙관 3개로 제시. 카테고리 내 대체 상품 잠식은 경고 문구로 표시 | 탄력성 추정에 쓴 행사 건수와 기간이 표시됨. 데이터가 부족한 SKU는 시나리오를 제공하지 않음 |
| 마진 방어선 체크 | P0 | 가격 추종 시 최소 마진율 미만 또는 역마진이 되는 SKU 경고. 최소 마진율은 카테고리별 설정, SKU별 예외 허용 | 방어선 변경 이력 기록. 경고 대상이 비교 시트에서 필터링됨 |

### 트렌드 및 격차

| 기능 | 단계 | 요건 | 수용 기준 |
| --- | --- | --- | --- |
| 키워드 빈도·점유율 연산 | P1 | 사내 검색어, 판매량, 경쟁사 노출 빈도를 카테고리별로 집계. 전주·전년 동기 대비 증감률 | 집계값이 원천 로그 재집계와 일치. 동의어 사전 적용 여부 표시 |
| 검색-판매 간극 진단 | P1 | 검색량 상위·전환율 하위 키워드 추출 후 원인을 아래 순서로 판정 | 표본 100건 검수 시 원인 분류 정확도 85% 이상 |
| 신규 상품 감지기 | P2 | 마스터 DB에 없던 경쟁사 상품과 자사 미입점 급상승 검색어 추출. 급상승 기준은 전주 대비 증가율과 최소 검색량 | 동일 상품의 명칭 변경이 신규로 잡히는 비율 10% 이하 |
| 할인 기간 이상 감지 | P2 | 행사 불발: 행사 기간 판매량이 기준선(직전 4주 같은 요일 평균, 전년 동기로 계절 보정) 대비 기대 상승폭에 미달. 장기 할인 고착: 최근 90일 중 할인 일수 비율이 임계값 초과 | 감지 건마다 기준선·실적·판정 근거가 표시됨 |

간극 원인은 위에서부터 처음 해당하는 항목을 주원인으로 하고, 나머지 해당 항목은 부원인으로 함께 표시한다.

1. 상품 부재: 키워드에 매핑되는 자사 판매 상품이 없음
2. 품절: 매핑 상품의 기간 내 품절 시간 비율이 임계값 초과
3. 가격 열위: 표준 단가가 경쟁사 최저 실구매가보다 임계값 이상 높음
4. 기타: 위에 해당하지 않음(노출 순위, 상세 페이지 등 수동 확인 대상)

## 7. 모듈 4: 대시보드 및 관리

화면은 조회에서 끝나지 않고 가격 변경 제안과 승인까지 이어지며, 모든 수치에 데이터 기준 시각을 표시한다.

| 기능 | 단계 | 요건 | 수용 기준 |
| --- | --- | --- | --- |
| 가격/마진 비교 시트 | P0 | 자사가, 경쟁사 실구매가와 표준 단가, 현재 순마진율, 매칭 시 예상 마진율, BEP 판매량, 매칭 등급, 기준 시각. 정렬·필터·내려받기 | 대상 SKU 전체 로딩 3초 이내. 내려받기는 권한자만 가능하고 감사 로그에 기록 |
| 데이터 소스 관리창 | P0: 연결 상태·크롤링 타깃 설정 / P1: 백필 업로드 | 소스별 상태, 마지막 성공 시각, 실패 사유. 크롤링 URL과 주기 설정 | 설정 변경 이력 기록. 잘못된 URL은 저장 전 검증 |
| 키워드 및 상태 종합 현황판 | P1 | 카테고리별 키워드 트렌드, 검색-판매 간극 사분면 차트. 신규 감지 리스트는 P2 | 차트의 점에서 해당 키워드 상세로 이동 가능 |
| 프로모션 캘린더 | P1 | 자사·경쟁사 행사 기간을 타임라인으로 비교. 전년 동기 겹쳐 보기 | 백필된 행사와 현재 행사가 같은 축에서 조회됨 |
| 이상 징후 알림 | P1 | 역마진 위험, 경쟁사 최저가 갱신, 핵심 키워드 품절. 유형별 임계값, 같은 SKU·유형은 24시간 내 1회, 일반 등급은 일 1회 묶음 발송 | 수신자·임계값을 담당자가 설정. 알림 본문에는 원가·마진 수치를 넣지 않고 화면 링크만 포함 |
| 가격 변경 승인 흐름 | P1 | 비교 시트에서 변경안 작성, 승인자 검토, 승인 후 내보내기. 방어선 미만 변경안은 상위 승인 필요. 가격 시스템 자동 반영은 범위 밖 | 변경안마다 작성자·승인자·근거 스냅샷이 보존됨 |

## 8. 비기능 요건

원가와 마진은 민감 정보로 취급하며, 아래 항목은 P0부터 적용한다(비식별화는 검색 로그를 연동하는 P1부터).

| 영역 | 요건 |
| --- | --- |
| 권한 | 역할 기반 접근 제어. 원가·마진 열람, 내려받기, 방어선 설정, 가격 변경 승인을 별도 권한으로 분리. 사내 SSO 연동 |
| 감사 로그 | 조회·내려받기·설정 변경·매칭 변경·승인을 사용자·시각·대상과 함께 기록. 보관 기간은 사내 정책을 따름 |
| 비식별화 | 검색·주문 로그는 사용자 식별자를 제거하거나 집계한 형태로만 적재. 검색어에 섬인 개인정보(전화번호, 주소 등)는 적재 전 필터링 |
| 자격 증명 | DB·API 접속 정보는 비밀 관리 저장소에 보관. 소스 시스템에는 읽기 전용 계정으로만 접속 |
| 데이터 품질 | 수집 성공률, 적재 지연, 미매핑 코드 수, 단위 파싱 실패 수, 매칭 재확인 대상 수를 일 단위로 측정하고 임계값 초과 시 운영자에게 알림 |
| 신선도 표시 | 기준 시각이 수집 주기의 2배를 넘은 값은 화면에서 "오래된 값"으로 표시하고 알림 판정에서 제외 |
| 가용성 | 업무 시간 기준 대시보드 가용률 99%(제안값). 수집 장애가 대시보드 조회를 막지 않음 |
| 크롤링 준수 | 법무 검토를 통과한 대상·방식만 수집. 로그인이 필요한 영역과 개인정보는 수집하지 않음. 요청 빈도 상한 적용 |

## 9. 미결 사항과 리스크

아래 항목이 확정되기 전에는 P0 일정과 수용 기준 수치를 확정할 수 없다.

- [ ] 규모: 대상 SKU 수, 경쟁사 수, P0 카테고리
- [ ] 크롤링 대상 사이트별 약관·법무 검토 결과
- [ ] ERP에 과거 원가 이력이 남아 있는지, 소급 수정 빈도와 배치 주기
- [ ] 물류비·수수료·폐기율이 SKU 단위로 있는지, 없으면 배분 기준
- [ ] 판매가·원가의 부가세 포함 여부 통일 기준
- [ ] 카테고리별 최소 마진율과 설정 권한자
- [ ] 카드·멤버십 전용가를 비교 기준에 포함할지 여부
- [ ] 검색 로그의 개인정보 포함 범위와 활용 근거
- [ ] 매칭 검수 담당자와 주당 검수 가능 건수
- [ ] 알림 채널(메신저 종류)과 수신 대상

| 리스크 | 영향 | 대응 |
| --- | --- | --- |
| 신선식품 매칭 부정확 | 잘못된 가격 인하 판단 | 속성이 같을 때만 "동일" 등급, 확정은 사람이 수행 |
| 경쟁사 페이지 구조 변경·차단 | 가격 데이터 공백 | 구조 변경 감지, 오래된 값 표시, 알림 판정 제외 |
| ERP 원가 소급 수정 | 과거 마진 수치 불일치 | 이중 시점 적재로 수정 전후 모두 보존 |
| 탄력성 추정 데이터 부족 | 시나리오 신뢰도 낮음 | P2로 미루고, 데이터 부족 SKU는 제공하지 않음 |
| 알림 과다 | 알림을 무시하게 됨 | 임계값·중복 제거·묶음 발송, 운영 후 임계값 재조정 |
